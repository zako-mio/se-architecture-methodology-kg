5. 反思 / 分析 / 建议

5.1 最重要的教训：委托链上的「自证」必须收回

本轮最大收获不是增密本身，而是定位了一条隐蔽的失败模式：

子 Agent 无 shell 无法自检，其「读回后人工计数」不是测量，而是断言——
三轮 20+ 工人自报字数恒落在目标区间，与机器实测毫无关系。

这个模式极其危险，因为每个工人都回报 success，若主Agent 采信自述， 残缺内容会直接进入 SSOT 并污染公开层。防线是 fail-closed 的门控： G-D3 与装配器当场拦住了全部 26 个不达标稿，未让任何残缺内容落盘。

建议固化为纪律：凡子 Agent 产出可机械度量的产物（字数、行数、条目数、哈希）， 度量权一律归主Agent，工人只产出内容、不报数字。

5.2 判据可信度：负向测试是本轮最值得保留的资产

negative_test_densify.py 是本项目首次对增密门控做可证伪性验证（11/11 如期）。 它当场证明了 G-D3（字数）与 G-D4（版权）真的拦得住——而这正是本轮 W2 的实际失败模式。 建议纳入常态回归：新增或修改任何门控，必须同时提交负例。

5.3 方法论层面：本次增密是「纯内容深化」

26 节点 verified / confidence 值零翻转（G-D5 实测），verified=true 占比 89.22% 与阶段1 完全持平。即本轮未借增密之名改动核验结论——这验证了 「增量式回写 + 保守终裁」的架构是稳的。

2. 制定计划

2.1 以拷问式收敛替代「拍脑袋」

本轮采用逐分支拷问（grill-me）而非直接出稿：每个分支先摆多维权衡矩阵，再请用户裁决。共收敛 12 个分支，全部有明确出处与理由。

用户在过程中两次主动要求「先权衡再决策」，因此自 Q4 起每个分支都先给出「并发安全 / 保真度 / 成本 / 可续跑 / 可机检」等维度的量化对比，再提问。

2.2 最关键的一次权衡：SSOT 回写口径

三个候选是「段级锁定 + 新事实强制回写」「句级全量映射」「等价重述优先」。权衡结论：

  • 句级全量映射：溯源最细，但「实质句」无法定义 → 判据不可机检、易假 FAIL、且会灌入无意义 claim；
  • 等价重述优先：默认零新增 claim，成本最低，但无法引入书证的机制/权衡/案例 → 与「增密」目标根本相悖；
  • 段级锁定：claim 的 origin 本就映射五段（definition/principle/mechanism/engineering/tradeoff），粒度天然对齐、可机检、成本可控。

关键洞察：保守项不是竞争项而是分支——「无新事实时本就不必新增 claim」。最终口径 = 段级强制 + 无新事实豁免 + 句级降级为抽检 WARN + 改写前 claim 完整性前置核查。

5. 反思 / 分析 / 建议

5.1 关键认知

  1. 「增密」的真实风险不在"写得少"而在"写得越界"。阶段1 的 FP 率为 18.75%，其形态是「书中原句 + 我们的推断扩展」被误判；阶段2 要写 40–70% 新正文，同类失真只会放大。因此质检设计必须先于内容设计——本轮把「正文 vs 素材」保真复核列为强制第二层，是直接针对该形态的对策。
  2. SSOT 的敌人不是"不写回"，而是"回写的粒度选错"。句级映射看似最严，实则因判据不可定义而形同虚设；段级之所以成立，是因为阶段1 的 claim.origin 恰好按五段切分——前一轮的数据设计决定了后一轮的可机检上限。
  3. 范围收敛本身就是风险控制。排除 9 个无 direct 锚节点，表面是"少做 9 个"，实质是拆除「为凑覆盖而注水」的诱因；配合 G-D5 对账，使"越界改写"从语义问题变成机检问题。
  4. 接力文档的自述仍需回盘。接力文档未记录「9 个 reverse-only 参与节点缺主张拆分」，该事实由独立复算得出，并直接改变了步骤 0 的设计（前置完整性核查从"优化项"变为"必需项"）。

5.2 建议

  1. Build 周期先小批验证再全量：先做 3–4 个节点跑通「证据展开 → 改写 → 双层复核 → 门控」全链，确认 L8 版式与 G-D4 红线口径无误后再放开 26 节点。
  2. G-V5 可顺势升级为复合主张检测（阶段1 已提此建议）：对「直陈 + 推断」复合主张主动告警，与 G-D4 形成互补。
  3. 证据展开素材可沉淀为阶段3 候选池：_densify/ 中按书整理的素材天然是「补引 / 新增节点」的输入，阶段3 规划时可直接消费，避免二次阅读。
  4. 剩余 27 本核验宜分批推进：每批完成后立即对该批新覆盖节点增密，避免"核验完再统一增密"造成的长尾等待与同一节点二次改动。

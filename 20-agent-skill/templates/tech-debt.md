# 技术债治理模板 · 技术债象限与重构优先级

> 对应工程步骤「实现/重构/技术债」（介入强度：按需级；主要场景 2、3、11）。
> 本模板为人类可读的技术债治理结构，**无独立 schema、不单独过门控**；
> 用于登记债务、归类象限、排定重构优先级，并明确偿还/容忍的门控点。
> 所有节点 id 须先在 `<MISSION_ROOT>/10-dag-data/methodology-dag.json` 中核实存在，禁止编造。

## 一、章节说明

| 章节 | 必填 | 内容 | 支撑节点（示例） |
|---|---|---|---|
| 债务清单 | 是 | 编号、描述、证据（可复核的事实，如坏味道统计 / 缺陷密度 / 变更成本） | `ESS-L-02`、`MTH-L-02` |
| 技术债象限 | 是 | 按「有意/无意 × 谨慎/鲁莽」四象限归类，并给偿还/容忍策略 | `MTH-L-03` |
| 影响面 | 是 | 关联模块/边界（可关联 `BD-xxx`）、受影响的场景与质量属性 | `MTH-L-06` |
| 重构优先级排序 | 是 | 依据「影响 × 成本 × 风险」排序，给出先后顺序 | `MTH-L-06`、`MTH-L-01` |
| 门控点 | 是 | 何时必须偿还、何时可继续容忍的判定条件 | `MTH-L-03`、`MTH-L-04` |
| 节点引用位 | 是 | `graph_refs`（ESS/MTH）+ `standards_refs`（TEC） | — |

> `graph_refs` 与 `standards_refs` 的分工同 ADR：
> 前者是"判据"（ESS/MTH）；后者是"标尺"（TEC），只作外部对照，不得进入偿还/优先级推荐位。

## 二、技术债象限（`MTH-L-03`）

| 象限 | 判断 | 典型策略 |
|---|---|---|
| 有意 × 谨慎 | 知情的前提下主动欠下、并有偿还计划 | 记录登记、按计划偿还 |
| 有意 × 鲁莽 | 知情但仍草率欠下、无偿还安排 | 补计划，限期偿还 |
| 无意 × 谨慎 | 不知情但开发规范良好，属自然演化 | 监控、择机偿还 |
| 无意 × 鲁莽 | 不知情且实践草率，属最危险象限 | 优先偿还，先止血 |

## 三、措辞纪律（刚性）

- `TEC-` 节点 id **不得**出现在「偿还策略」「重构优先级」等**推荐位**；
  `TEC-` 只允许写入文末 `standards_refs`。
- 引用技术实践层时统一用"以 `<TEC-节点名>` 作为选型标尺佐证"的措辞，
  **不得**写成"应选用 `<具体技术/厂商>`"。

## 五、填好的最小示例（场景 2/3 · 遗留系统技术债与重构优先级）

以下节点 id 均已核实在 `methodology-dag.json` 中存在：
`ESS-L-02`、`MTH-L-02`、`MTH-L-03`、`MTH-L-06`、`MTH-L-01`、`ESS-L-03`、`TEC-H-01`。

```markdown
# 技术债治理 · 网申遗留模块

## 1. 债务清单
| 编号 | 描述 | 证据 | 象限 | 策略 | 影响面 |
|---|---|---|---|---|---|
| TD-001 | 报表逻辑散落在多个处理器，边界模糊 | 单次报表变更平均触及 4 个模块 | 无意×谨慎 | 择机偿还 | 报表模块 / BD-002 |
| TD-002 | 关键路径缺自动化测试 | 关键路径测试覆盖率低于阈值 | 有意×鲁莽 | 限期偿还 | 核心模块 / BD-001 |

## 2. 技术债象限与策略
- TD-001：不知情造成、开发实践尚规范 → 无意×谨慎，列监控项，随下一次报表需求一并重构。
- TD-002：知情但为赶进度无偿还安排 → 有意×鲁莽，先止血补测试再谈重构。

## 3. 影响面
- 关联模块/边界：BD-001（核心）、BD-002（报表）
- 受影响场景与质量属性：报表变更（可修改性）、回归（可靠性）

## 4. 重构优先级排序
| 优先级 | 编号 | 影响 | 成本 | 风险 | 依据 |
|---|---|---|---|---|---|
| 高 | TD-002 | 高 | 中 | 高 | 无测试保障下任何改动风险放大 |
| 中 | TD-001 | 中 | 中 | 低 | 可随需求顺带偿还 |

## 5. 门控点
- 必须偿还：TD-002 须在下一次涉及核心模块的改动前完成。
- 可继续容忍：TD-001 在报表需求未启动前维持容忍，并登记监控。

## 6. 节点引用位
- graph_refs（ESS/MTH）：`ESS-L-02`、`MTH-L-02`、`MTH-L-03`、`MTH-L-06`、`MTH-L-01`、`ESS-L-03`
- standards_refs（TEC，仅选型标尺）：`TEC-H-01`
```

> 说明：示例中 `TEC-H-01` 仅作为 `standards_refs` 的选型标尺佐证，
> 未出现在「偿还策略」「重构优先级」等推荐位。

## 一、目标与约束

**目标**：把阶段2/3 产出的 14 个证据包（F–R，256 条信源）与 12factor 既有图谱，收敛为一座**可人读、可机读、可演进**的母库；直接消费方有两个：

1. **人读图谱**（主消费方）：学习者与开发者，判据是"读得懂、找得到、不误导"（kb-construction 内容交付型定义，`C/SK-01`）。
2. **Agent skill**（副消费方）：为 Agent 加持架构判断力，判据是"按需检索、低 token、单一事实源"。

**约束**：

- **版权红线（刚性）**：书籍/标准正文只入本地语料层，公开库只承载消化重组后的知识与自研脚本（`contract §5`）。
- **口径唯一**：术语以 `glossary.md` 为唯一裁决表（23 条裁决，settled 19 / disputed 4），定义基线不另立（`01-alignment §六`）。
- **不预设规模，但需粒度规则**：节点总数由证据包与 12factor 映射结果决定，先定规则再产节点，避免"先堆后拆"。
- **可执行**：本设计必须能被阶段5 直接翻译为任务与门控，而非理念宣示。

## 二、骨架主轴三方案对比（重点决策）

母库骨架主轴是什么，决定了数据模型、DAG 形态与所有视图。候选三案：

- **① 三层为主轴**：以「本质层 / 方法论层 / 技术实践层」为唯一组织维度。
- **② 生命周期为主轴**：以 F–N 十个生命周期域（概念需求→…→团队康威）为唯一组织维度。
- **③ 生命周期 × 三层矩阵**：节点同时携带"层坐标"与"生命周期坐标"，两层维度正交。

| 维度 | ① 三层为主轴 | ② 生命周期为主轴 | ③ 生命周期×三层矩阵 |
|---|---|---|---|
| 结构清晰度 | 高（层义明确） | 高（叙事顺） | 中（需双层治理，规则清晰后仍高） |
| 与 D1（本质 vs 具体方法边界）解耦的契合 | **最高**（层即边界） | 低（本质/方法/技术混于同域） | **高**（层仍是规范边界，仅多一语境轴） |
| 与阶段2 搜索产物（F–N 按生命周期采集）衔接成本 | 高（需把 F–N 重映射到三层） | **最低**（一比一） | 低（domain 直接继承 F–N） |
| DAG 依赖可表达性 | **强**（层间单向依赖倒置） | 弱（同域内异层关系难表达） | 强（层轴定方向，域轴只分组） |
| 多视图生成难度 | 中（生命周期视图需另造） | 低（生命周期视图天然） | 低（同一模型派生全部视图） |
| 演化成本 | 中（新域无处安放） | 高（新知识污染层边界、技术过时无法隔离） | 低（新域=新坐标；技术层可替换） |
| **推荐度** | ⭐⭐ | ⭐ | **⭐⭐⭐（推荐）** |

**明确推荐：方案 ③，但采用"非对称矩阵"**——**三层为规范轴（primary）**，决定依赖方向、D1 解耦与"技术过时隔离"；**生命周期为语境轴（secondary）**，决定分组、检索与视图。理由：

1. 它同时满足两条硬约束：D1 解耦（只有三层轴能给"本质 vs 具体方法"划界）与 F–N 对接（只有生命周期轴能直接继承阶段2 采集结构）。
2. 方案 ② 最省衔接成本，但**无法隔离易过时的技术内容**，等于放弃用户"架构设计也要应用于该库自身"的核心诉求——本质与方法会被工具版本淹没，反例正是"12-Factor 条款"与"K8s 命令"混在同一域。
3. 方案 ① 结构最纯净，但会丢失生命周期叙事（本库面向"全生命周期管理"的立场，`01-alignment §五`），并把 F–N 十域变为孤儿，多视图成本外溢。
4. 非对称（而非完全对等矩阵）是为**避免矩阵爆炸**：一个知识点只落一个坐标对，边只走"层方向"，生命周期仅作分组/滤镜——这是"以受控复杂性换取解耦与对接"的显式权衡（见 §十二）。

> 决策记录（ADR 式）：**Context**＝三约束冲突；**Decision**＝非对称矩阵；**Consequences**＝数据模型字段增加、需层边界与粒度规则治理，但获得 D1 解耦与 F–N 零重映射对接。

## 三、三层内容解耦设计

### 3.1 层边界判定规则（什么进哪层）

| 层 | 回答 | 判据（全部满足才归入） | 示例（含来源） |
|---|---|---|---|
| **本质层 essence** | 为什么 | 换语言/框架/年代仍成立；与技术无关；是对抗复杂度的根本概念或定律 | 本质复杂度四要素（`F/S4-04`）、信息隐藏（`H-S2-01`）、内聚/耦合（`H-S2-09`）、依赖规则（`B-S2-06`）、Lehman 演化定律（`R-XC-01`）、康威定律（`N/S2-01`）、11 维权衡思维（`O-TD-01..11`） |
| **方法论层 methodology** | 怎么做 | 跨项目可迁移的过程/方法/决策框架；不绑定具体工具与版本 | 需求工程过程链 BRS→SRS（`F/S1-F02`）、QA scenario 六要素（`F/S2-F01`）、ADR/ATAM（`B-S2-09`、`G/S1-11`）、测试金字塔（`I/S2-WEB-12`）、重构手法族（`L/S2-04`）、弃用三级信号（`L/S1-02/03`）、DDD 战略设计（`B-S2-08`）、团队拓扑（`N/S2-05`） |
| **技术实践层 technology** | 用什么做 | 有版本号/厂商/可被替代的具体工具、框架、命令行、平台条款 | 12-Factor 条款（`C/BK-01`）、K8s/不可变基础设施实现（`J/S3-05`）、OpenTelemetry（`K/S3-02`）、SonarQube/SQALE-TDR（`P-S4-02`）、AWS/GCP Well-Architected 支柱（`Q/S3-VEN-02/04`）、Thoughtworks Radar 环位（`Q/S3-VEN-06`） |

**边界争议处理**：若一个知识点同时含"稳定原理"与"工具实例"，**拆成两节点**（如"不可变基础设施"（方法论）↔"K8s 声明式部署"（技术）），用 `implements` 边连接，而非合并。

### 3.2 层间引用方向（依赖倒置）

```
技术实践层  --implements-->  方法论层  --derives_from-->  本质层
（外层，易变）              （中层，稳定）              （内层，最稳定）
```

- 源码级规则：**内层不得引用外层**（Clean Architecture 依赖规则，`B-S2-06`）。本质层节点中**不得出现任何工具名与版本号**；方法论层以本质层为"依据"，技术层以方法论层为"实现"。
- 反向引用（如本质→具体工具）**禁止建边**，如需关联只用 `case_instance` 案例边或视图染色表达（复用 cytoscape 经验：跨层关系用属性而非建边，`C/SK-03`）。
- 该方向同时保证主干 DAG **无环**（层单向 + 域内 prerequisite），便于 Kahn 拓扑校验（12factor 门控项 4）。

### 3.3 技术实践层"易过时隔离"机制

| 机制 | 做法 | 依据 |
|---|---|---|
| **可替换** | 每个技术节点声明其 `implements` 的方法论节点；同一方法论可有 N 个技术实例。技术节点失效只波及自身 | 依赖倒置 / `H-S2-01` |
| **可下钻** | 技术层不作为学习路径主干，仅从方法论节点下钻进入 | 分级深度（`C/SK-01 §2.1`） |
| **可弃用标注** | 技术节点带 `status`(active/deprecated/superseded) + `review_date` + `version`；弃用走 deprecation→sunset→removal 三级信号 | `L/S1-02/03`（RFC 9745/8594、semver） |

**隔离墙**：本质层/方法论层节点编辑不触发技术层重建；技术层更新只改自身字段。这使"技术过时"不污染"方法论稳定"。

## 四、节点粒度规则

**什么算一个节点**（四条全满足）：

1. **单一主张**：有唯一核心原理/机制/决策（对应一条 ADR 级判断）；
2. **可承载**：能被五段式（定义/原理/机制/工程/权衡）完整表达，正文目标 1500–3000 字（对齐 12factor 节点规模，`C/KG-01`）；
3. **可引用**：有稳定 `id`，可被其他节点作为依赖目标；
4. **单坐标**：在"层"与"生命周期"各只有一个落点。

**正反例**：

- ✅ 正例："信息隐藏"、"测试金字塔"、"不可变基础设施"、"逆向康威"。
- ❌ 过大："架构设计"（应拆为几十节点）、"微服务"（拆为定义/粒度/去中心化数据治理/容错设计）。
- ❌ 过碎："日志级别"（并入"可观测性"小节）、"DRY 的字面定义"（并入"DRY 原则"节点）。

**量化启发式**：一个节点最多对应 **1 个** 11 维权衡轴主条目；若需 >5 段结构或横跨 ≥3 个生命周期域 → **拆分**；若两候选 >70% 内容重叠或总被同引 → **合并**。这直接防止"过大不可复用 / 过碎碎片化"。

**节点元数据字段建议**：`id / name(zh) / en / layer / domain / type / stage / priority / definition / sources[] / verified / confidence / review_date / status / tags / group / case[]`（下节详列）。

## 五、数据模型

在 12factor `meta/groups/nodes/edges`（node=`{id,name,en,type,src,group,stage,definition}`，edge=`{from,to,type,label}`，5 类边）基础上**扩展而非重写**（`C/KG-01`）。

**node 字段表（★=新增）**：

| 字段 | 取值/类型 | 说明 |
|---|---|---|
| `id` / `name` / `en` | string | 稳定 ID、中英文名（ID 方案见 §八） |
| `layer` ★ | essence\|methodology\|technology | **规范轴**，决定依赖方向与 D1 边界 |
| `domain` ★ | F…N 十域 + `cross` | **语境轴**，继承阶段2 生命周期域 |
| `type` | principle\|method\|technology\|bridge\|case\|tool | 节点类别（可含 crosscut） |
| `group` / `stage` / `priority` | string | 组；难度 basic/intermediate/advanced；P0–P3（继承算法库） |
| `definition` | string | 一句话定义（中文） |
| `cross_cutting` ★ | [M,P,N…] | 横切主题归属（质量/技术债/团队） |
| `case` ★ | [case-id] | 关联实战案例（PA-01..18 提炼） |
| `sources` ★ | [source_id] | 证据来源（引 `02-research`） |
| `verified` ★ | true\|false\|"cited" | 信源核验状态 |
| `confidence` ★ | high\|medium\|low | 置信度（disputed 术语须标） |
| `review_date` ★ | ISO date | 易过时控制字段 |
| `status` ★ | active\|deprecated\|superseded | 技术层生命周期 |
| `errata` ★ | [{misconception, verified_value, source_id}] | 勘误（如 Lehman 条数、Royce 瀑布误读，`R` 包） |

**edge 类型扩展**：保留 12factor 5 类（`prerequisite / variant / combination / cooccurrence / dependency`），**新增**：

- `implements`：技术层 → 方法论层（实现关系）；
- `derives_from`：方法论层 → 本质层（依据关系）；
- `cross_reference`：母库 ↔ 12factor 等的跨体系对照；
- `case_instance`：案例 → 知识节点（印证/违背）；
- `supersedes / deprecated_by`：版本演化。

**层间只允许 `implements`/`derives_from` 单向边**，是"依赖倒置可表达"的硬保证。

**承载横切主题**：用 `cross_cutting` 属性 + 独立 `crosscut` 组（继承 12factor `GX1–GX3`），配专题视图；横切节点**不建跨层边**，用染色表达（`C/SK-03`）。技术债（P 包 27 源）与质量（M 包）横切质量属性域。

**承载案例层**：案例作为 `case` 类型节点（或独立 `cases.json`），经 `case_instance` 边指向其所印证/违背的方法论/本质节点。案例**不阻塞主干 DAG**，可离线加载，避免 18 个实战留档（`C/PA-01..18`）把总图撑爆。

## 六、多视图设计

全部视图从**同一** node/edge 数据模型派生（禁止硬编码，双轨交付原则 `C/KG-03`）。

| 视图 | 数据来源 | 生成方式 |
|---|---|---|
| **总览** | groups + nodes 全量 | 组级 cytoscape 图 + 点击下钻（复用 12factor 两级视图） |
| **分层视图** | `layer` 过滤 + `implements`/`derives_from` 边 | 三层依赖图（本质在内、技术在外的同心/分层布局） |
| **学习路径** | `stage` + `priority` + `prerequisite` 边 | 按难度与依赖拓扑排序的路径页（继承 12factor 三路径 + 算法库 P0–P3） |
| **决策矩阵** | O 域 11 维权衡（`O-TD-01..11`）+ 36 原则↔反例（`O-PC-01..36`）+ ATAM 术语 | 表/矩阵视图（权衡轴 × 场景） |
| **跨体系对照** | `cross_reference` 边 + 12factor App↔Agent 对照模式 | 对照表页（继承 `04-cross-mapping`） |
| **案例视图** | `case` 节点 + `case_instance` 边 | 按案例/项目组织的索引页（PA-01..18） |

> 生成难度收敛：除总览需组级下钻外，其余 5 视图均为"字段过滤 + 布局变换"，由通用生成框架统一产出。

## 七、12factor 双层纳入 + 双向互链

**纳入机制**（D4 决策：12factor 为"最终母库、按其架构纳入"，`report.md`）：

- **节点映射规则**：12factor 38 节点（12 App + 12 Agent + 10 桥接 + 4 工具，`C/KG-01`）按三层轴归类：12-Factor 条款 → 多数落 `technology`（少数如 build/release/run 分离落 `methodology`）；10 个桥接主题 → 落 `essence`/`methodology`；Agent 原则 → 落 `technology`（AI 原生工程分支）。每个 12factor 节点挂 `case_instance` 边指向母库对应方法论/本质节点。
- **案例层实例形态**：12factor 库作为母库的**首个子库/实例库**，整体以 `cross_cutting` 专题（部署域 + AI 原生工程）呈现，而非把 38 节点内联进母库主 DAG（避免 ID 冲突与双份漂移）。
- **深链格式**：`../../0823-12factor-methodology/02-node-pages/<node-id>.html`（相对）或 `https://<host>/12factor/<node-id>`（在线）。
- **回链约定**：母库节点页设"实践资源"区块列 12factor 深链（复用 12factor `08-source` 双区块模式）；12factor 节点页加"母库对照"回链。双向链接由生成脚本产出，**禁止手改**（`C/SK-01` 双轨原则）。

## 九、D5 Agent skill 形态优缺点分析

| 方案 | 优点 | 缺点 | 推荐 |
|---|---|---|---|
| **A 单一 skill + 路径路由** | 单入口；prefix-cache 友好；维护点集中 | skill 体积膨胀；加载全文成本高；触发描述宽泛 | 部分采纳（路由骨架） |
| **B 多 skill 分主题** | 按需加载精准 | 触发词冲突；跨 skill 依赖难维护；碎片化 | ✗ |
| **C skill 仅轻量速查** | 极省 token；与图谱单一事实源；深链跳转 | 深度内容不在 skill，需读库文件 | **✓（主）** |
| **D 只出计划（如何检索）** | 最轻 | 价值低，等同路由说明 | ✗ |

**推荐：C 为主 + A 的路由骨架**——skill 仅承载"高频速查表 + 三层/生命周期导航 + 深链到人读图谱"，知识主体留在图谱（单一事实源）。理由：避免知识双份漂移（DRY 与信息隐藏，`O-PC-06`/`H-S2-01`）；skill 前缀稳定小符合 prefix-cache；Agent 需要深度时深链读库即可。

## 十、建库执行方式优缺点分析

| 方案 | 优点 | 缺点 | 推荐 |
|---|---|---|---|
| 复用 12factor 生成链（原样） | 即用、经 61 HTML 门控验证、40 分钟全量 | 面向 38 节点优化，字段/视图不匹配三层+矩阵 | ✗ |
| **复用 + 重构为通用框架** | 继承验证过的工程底座（`gen_common.py`+5 生成器，已跨 12factor/open-code-review 复用）+ 适配新模型 | 有前期重构成本（约 1–2 天） | **✓（推荐）** |
| 全新重写 | 完全贴合 | 重复造轮子、丢失门控与经验、风险高 | ✗ |

**推荐：复用 + 重构为通用框架**——把 `gen_common.py` + 5 生成器参数化为"数据模型 / 渲染引擎"解耦的骨架（关注点分离），增加 `layer/domain/case/多视图` 支持。这是"以可接受的确定性前期投入换取工程可控与可演进"的权衡（`O-TD-04`：一次性成本 vs 持续成本，优化持续成本）。

## 十一、阶段5 建库计划（到可计划粒度）

**波次划分**：

- **Wave 0 · 契约与骨架**：落盘统一 ID 方案 + node/edge schema（§五）+ P0 契约 + 通用生成框架重构（§十）+ 小批量试点（12factor 38 节点回归）。
- **Wave 1 · 本质层 + 方法论层节点生产**：从 F–O 证据包 + 11 维（`O-TD`）+ 36 原则↔反例（`O-PC`）+ 23 术语裁决（`glossary`）提炼。按域分批（F/G/H/I/J/K/L/M/N/O），每批 8–14 节点、每波 5–8 并行（`C/SK-01 §六`）。
- **Wave 2 · 技术实践层 + 案例层**：12factor 38 节点映射纳入（§七）+ PA-01..18 案例提炼 + 技术节点（K8s/OTel/SonarQube/Well-Architected）。
- **Wave 3 · 多视图 + 深链**：生成 6 类视图（§六）+ 双向互链（§七）。
- **Wave 4 · 门控与留档**：L1–L7 + 方法论专项 + 报告双版本（MD+HTML）。

**内容生产流程**（基于 F–R 证据包）：每节点五段式（定义/原理/机制/工程/权衡），`sources[]` 作锚点；主Agent 只编排/聚合/裁决，内容生产全委派子Agent；**先落盘再返回**（`contract §7`）；批次跟踪 `_batch-plan.json`，每波前读盘核对；文件名按域+批次唯一（防同名覆盖，`MEMORY` 经验）。

**门控映射（L1–L7 + 方法论专项）**：

| 层 | 查什么 | 阶段5 落点 |
|---|---|---|
| L1 生成时自验证 | schema 合法、关键样例 | 子Agent 自测 node/edge JSON 可解析 |
| L2 全量审计 | 字段完整性、命名归一、跨产物一致 | 全节点字段非空、ID 统一（§八） |
| L3 结构 | UTF-8/U+FFFD、断链、空文件、**空正文** | 全部 HTML/MD；深链可达为 0 断链 |
| L4 视觉 | 架构图防截断（drawio/PIL） | 分层图、决策矩阵图 |
| L5 渲染 | cytoscape 实渲染 canvas/节点计数/无 JS 错 | 总览/分层/跨体系交互图（headless Chromium） |
| L6 覆盖度 | 节点/视图/案例/深链矩阵逐项核对 | DAG↔节点页↔MD↔案例四向覆盖 ≥90% |
| L7 信源 | verified/证据区块/≥2 源交叉 | 可溯源率 ≥95%，disputed 术语显式标注 |

**方法论专项门控**：① 层边界判定规则校验（无内层引用外层、无技术→本质直连边）；② 术语一致性（`glossary.md` 唯一裁决）；③ 原则↔反例配对完整性（每条 `O-PC` 必须入库且配反例）；④ 11 维权衡覆盖（`O-TD-01..11` 均有落点）。

## 十二、架构风险与权衡

架构是权衡而非对错（ATAM 态度，`G/S1-11`）。本设计显式列风险与取舍：

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 矩阵模型复杂 → 边界模糊/重复节点 | 数据质量下降 | 层边界规则（§三）+ 粒度规则（§四）+ 双向门控 |
| 2 | 本质层"薄而抽象"，被技术层淹没 | D1 解耦名存实亡 | 学习路径以本质为根；本质节点宁精勿多 |
| 3 | 技术层过时 | 误导 | `implements` 边解耦 + `review_date`/`status` + 弃用三级信号 |
| 4 | 12factor 纳入 → ID 冲突/双份漂移 | 断链、库内矛盾 | 统一 ID 方案（§八）+ 12factor 为子库单一源 + 禁止复制内容 |
| 5 | 版权违规 | 法律风险 | 书本体只入本地语料层；技术节点只引官方公开文档链接 |
| 6 | 生成链重构成本/回归 | 进度与稳定性 | 增量重构 + 38 节点试点回归 + 全量门控 |

**核心取舍（Named Trade-offs）**：

- 选**矩阵**换 D1 解耦与 F–N 零重映射，代价＝数据模型复杂与治理成本（§二）。
- 选**skill 轻量化**换单一事实源与低 token，代价＝Agent 需深链读库（§九）。
- 选**复用生成链**换工程确定性，代价＝前期重构投入（§十）。
- 一切"够用就好、简单优先"（`O-TD-03/08`）：不建检索层（D2 维持挂起），除非出现明确跨域检索需求——避免为"未来可能需要"过度设计（YAGNI，`O-PC-07`）。

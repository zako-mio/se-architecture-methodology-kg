# 公开文档措辞规范（public-wording-policy）

> 适用范围：所有将进入 `_publish/`（公开仓）的文本类产物
> （`.md/.html/.json/.txt/.yml/.yaml/.css/.js/.svg`）。
> 门控：`16-checkpoint/gate_disclosure.py`；豁免：`16-checkpoint/disclosure-allowlist.txt`。
> 版本：v1.0 ｜ 2026-09-11

## 1. 为什么需要本规范

- 公开仓只承载「消化、重组、自研」的内容：概念解释、方法论归纳、结构化数据、索引与导航。**采集过程的痕迹不属于公开交付面**。
- 采集渠道、来源合法性、版权风险状态等表述一旦公开，会带来三类问题：暴露私有语料层的获取路径；引发版权与合规风险；被搜索引擎与镜像站抓取后**不可撤回**。
- 因此采用 **默认拒绝（fail-closed）**：公开文本类产物出现任何披露口径词，发布门控直接 FAIL，阻断 Pages 部署，而不是发出警告。

## 2. 禁用表述表

## 3. 允许与豁免机制

- **优先改写**：绝大多数命中应通过改写措辞消除，而不是豁免。
- 豁免清单 `16-checkpoint/disclosure-allowlist.txt` 用法：
  - `相对路径 :: 豁免词`：仅豁免该文件的某一个词。
  - `相对路径 :: *`：豁免该文件（或以 `dir/` 表示的前缀目录）内的全部禁用词。
  - 豁免必须逐行显式声明，并在提交说明中写明公开必要性；**不得**用 `*` 覆盖整个公开仓。
- 边界与纪律：
  - 豁免只作用于**披露措辞门控**，不改变版权/合规判断；豁免某文件不等于允许公开其第三方正文。
  - 门控登记簿自身（allowlist）被跳过，以便书写禁用词；其余被扫描文件零容忍。
  - 正文级版权判断仍由 `audit_publish.py` 负责，两者互补、互不替代。

## 4. 提交前自检

```bash
python3 -m py_compile 16-checkpoint/gate_disclosure.py
python3 16-checkpoint/gate_disclosure.py --root . --quiet   # 期望 0 命中
python3 16-checkpoint/gate_disclosure.py --root . --json    # 结构化命中清单
```

CI 中同一门控在 `assemble_publish.py --export` 之前运行，命中即阻断部署。

## 5. 维护约定

- 词表只在 `gate_disclosure.py` 的 `_TERM_PARTS` 维护，**必须保持分片写法**（源码中不得出现完整禁用词）；新增词需同步更新本表与门控常量。
- 修改本规范后，运行第 4 节自检，确认本文件自身零命中。

§2成员节点目录

节点 ID名称层/来源阶段简介
ESS-L-01软件演化定律本质 essence高级描述 E 型软件在持续演化中反复出现的规律：系统必须持续变更否则逐渐失效，而持续变更又使复杂度递增、质量下降，需要以自我调节与反馈治理。它把演化视为常态而非异常。它把演化确立为需要持续投入的常态过程。
ESS-L-02技术债本质本质 essence进阶技术债是用短期便利换取长期变更成本的设计权衡，其本质是经济取舍而非道德评判：审慎而有意的债务可加速交付，判断标准是债是否审慎、是否被及时偿还，而非是否存在。
ESS-L-03架构侵蚀与漂移本质 essence高级架构侵蚀是违反既定架构约束的改动导致的系统脆化，架构漂移是对架构不敏感的改动导致的逐渐失一致；两者共同使系统越来越抗拒变更，是架构层腐化的两种机制。
ESS-L-04演化的不可逆性本质 essence进阶成功投入使用的软件必然持续被修改，且演化在方向上是不可逆的：需求、环境与依赖的变化使系统无法回到先前状态，冻结系统只会加速其价值衰减。
ESS-L-05变更成本随复杂度增长本质 essence进阶系统复杂度随规模与演化不断增长，使每次变更所需的理解、修改与验证成本持续上升；治理的核心是在演化中抑制这条成本曲线的斜率，而非追求一次性的低复杂度。
MTH-L-01行为保持重构方法论 methodology基础在不改变可观察行为的前提下重组软件内部结构，使其更易理解、更易修改；判定重构是否成立的硬标准是行为不变，治理要点是把小步变换持续进行而非安排一次性大改。
MTH-L-02代码坏味道启发式方法论 methodology基础把代码中易于察觉的表层迹象作为可能指向更深层结构问题的启发式信号，用以发现重构对象与时机；坏味道提示「值得检查」，但不等于「一定有问题」，不能机械照改。
MTH-L-03技术债象限与偿还策略方法论 methodology进阶以「有意/无意」与「审慎/鲁莽」两组正交判据对债务分诊，据此制定差异化偿还策略：审慎有意者计划偿还，审慎无意者随认知更新修正，鲁莽者立即纠正，并按变更热点优先偿付利息最高的债务。
MTH-L-06遗留系统渐进治理方法论 methodology高级对难以安全修改的遗留系统，先以接缝与特征测试建立覆盖既有行为的安全网，再以绞杀者方式增量迁移新功能、逐步替代旧系统，避免缺乏保护的大规模重写。
MTH-L-07弃用与日落策略方法论 methodology进阶对将被淘汰的能力采取分级的退场流程：先发出弃用信号并提供替代与迁移路径，留足通知期，再按版本语义区分兼容的弃用与破坏性的移除，从而在收敛接口的同时不破坏既有依赖。
MTH-O-10增量演化与一致性治理方法论 methodology高级在演化中治理一致性：优先用增量同步、契约与弃用信号替代全量重建，用适应度函数持续防止架构漂移，并以 expand/contract、绞杀者等模式渐进迁移，使变更小批量、可回退。
ESS-H-09设计模式与反模式本质 essence进阶设计模式是对反复出现的设计问题所给的可复用解法模板，提供团队共同语言但不保证适用；反模式是初看合理却适得其反的常见解法，二者把设计经验的正反两面固化为可传承的知识。
MTH-H-03战略式编程与持续设计投入方法论 methodology进阶一种把系统设计视为贯穿开发全过程的持续投入、而非开工前一次性阶段的编程纪律：以持续、小步的设计改进对抗复杂度的累积，使系统长期保持易于理解与修改。
CAS-X-04网申 v2 深度重构高级一次由「改一处漏多处」症状触发的深度重构：定位到接口定义散落 12 个文件、存在 7 种接口形态的根因后，以单一契约源、dispatch 消息表与能力注册中心重建三层契约系统，恢复可审计与可校验性。
CAS-X-05preset 通道耦合分析高级对 harness「委派工具层→续用管理器→preset 服务→MCP 服务器」这条通道做耦合分析：识别契约、服务定位、数据契约、组合语义、路径与装配一致性六类耦合点，定位「静默丢弃特化」与「装配漂移」两处实质缝隙。
CAS-X-06插件 DAG RC5→RC7 升级高级一次知识库随上游源码版本升级的级联维护：以三层差异分析把 219 个包收敛为 26 个实质变更包，经编译、运行时、组合三类依赖判定更新 DAG 数据后全量重生成页面，并以静态门控加渲染验证收口。
CAS-X-07插件 DAG 两次级联升级高级在同一知识库上继续两轮上游级联升级：处理数百次提交与包的增删，暴露「依赖声明不等于运行时引用」、分层须按最长路径深度、纯外部依赖边不得入主图等差分陷阱，并以全量门控校验收口。
CAS-X-08dsh-manager 插件深度分析高级以「编译依赖、运行时注入、组合装配」三硬依据加源码行号，对第三方插件做依赖、功能、需求溯源与设计问题裁决，并复用上游 DAG 知识库节点标识，使分析结果可与主图互查。
CAS-X-10dsh 插件依赖增量定位进阶以官方插件 DAG 为蓝本，对一个官方清单之外的全新社区插件做功能定位与依赖位置增量分析，产出可下钻交互依赖图与多形态文档的源码级架构逆向案例。
CAS-X-12MCP 四件套选型对比进阶对四个同类 MCP 服务器做源码级能力与成本对比，并以常驻 token 预算为轴给出分级接入策略的技术选型实战案例。
CAS-X-14OpenSpec 规约驱动解析进阶对比规约驱动开发工具链 OpenSpec 与 Superpower 的元模型、工件依赖 DAG 与安全门控，提炼「规约先于实现」工程形态的解析案例。
CAS-X-15Open Code Review 图谱高级对阿里开源 AI 代码审查 CLI 做源码级解析并构建「知识 + 实践资产 + AI 索引」三合一知识图谱的工程案例。
CAS-X-16控制理论⊗Agent 设计高级将控制理论五维（负反馈 / 状态估计 / PID / 鲁棒 / 分层）系统映射到 Agent 工程环节，并以真实产品案例验证的跨学科方法论案例。
TEC-F-02需求技术债识别与度量技术实践 technology高级识别并度量需求技术债——理想规格与实际实现之间的差距——的技术做法，把需求层的债务纳入技术债管理（TDM）的识别与度量阶段，使需求质量缺口可被发现与跟踪。
TEC-H-01SonarQube 静态分析平台技术实践 technology进阶SonarQube Server 是面向持续集成的静态代码分析平台，以规则引擎自动检测代码坏味道、缺陷与安全热点，并通过质量门控把分析度量转化为变更准入判断，同时区分整体代码与新代码以支撑增量治理。
TEC-H-02SQALE 技术债评估方法技术实践 technology高级SQALE 是一套以生命周期期望为基准、力求客观可复现地评估源代码质量并量化技术债的方法，由若干基本原则与质量模型、分析模型、指数、指标等组件构成，供组织与厂商实现。
TEC-H-03技术债量化度量指标技术实践 technology高级技术债量化度量把代码缺陷折算为可计算的债务规模与比率：以修复成本累加得到技术债额，用技术债比率（债务与开发成本之比）映射可维护性评级，并区分整体代码与新代码以支撑增量治理。
TEC-J-02不可变基础设施实现技术实践 technology进阶不可变基础设施实现指部署后的实例不再被就地修改，任何变更都通过从受测基础镜像重建新实例并替换旧实例来完成，从而消除运行期配置漂移。
TEC-L-02绞杀者渐进式替换技术实践 technology高级在遗留系统之上或之旁增量构建新实现，通过可切换的接缝与路由逐步把功能与数据迁移过去，逐步替代旧系统，而非一次性整机重写。
TEC-M-02可维护性量化技术实践 technology高级把可维护性与技术债转写为可计算指标：以修复违规的成本估计债务本金、按对可维护性的影响折算利息，沿质量子特性组织规则与评分，使变更成本可比较、可追踪。
MTH-H-01重构手法族方法论 methodology进阶在不改变可观察行为的前提下，按命名的小步手法持续改善代码内部结构的方法族；以代码坏味道为信号、以测试为安全网，把结构调整为可验证的小步而非大重写。
